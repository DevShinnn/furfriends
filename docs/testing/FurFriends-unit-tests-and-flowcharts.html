How the tests were run

  • Run: October 29, 2026 at 8:24 AM (Philippine time), with npm run test:report. The results tables below are filled in from that run, not typed by hand.
  • Tools: Vitest 3.2.4 in a simulated browser (jsdom 26.1.0), React Testing Library 16.3.0, Node v22.11.0.
  • What is tested: the app's real code (forms, the data store, scheduling, reminders, breed and emergency content, the clinic search and the assistant's safety rules). Each test is tagged with the requirement it checks.
  • Test doubles: Supabase is replaced by an in-memory fake that records every database call, and TomTom by recorded answers, so tests never touch the live database or use the free TomTom searches. Date tests use a fixed clock: Thursday 29 Oct 2026, 10:00 AM.
  • Do the tests catch mistakes? Before this run, three rules were broken on purpose (password length, the clinic filter, the dose refusal). The matching tests failed each time, and passed again once the code was restored.

Not covered by unit tests

Web push when the app is closed (UC4)Runs in Supabase's send-reminders edge function on a schedule, outside the app. It uses the same rules as the tested src/lib/reminders.js. It was checked end to end on the live project on 19 Oct 2026 (one real notification sent, none on the rerun).
Live TomTom data (UC7)The tests use recorded TomTom answers. The live find-clinics function was checked on 29 Oct 2026: 11 clinics for Batangas City, a repeat search served from the saved search, an address search for Lipa City, and a refusal when not logged in.
Map display and Google Maps app (UC7, UC8)Drawing the map and opening Google Maps happen in the browser and the phone; the tests check the exact links the buttons open.
Forgot passwordListed in the project proposal but not built: the log-in page has no password reset.
